# ✈️ Трекер вкусных билетов Италия → Шри-Ланка / Таиланд

Бот проверяет цены на билеты **туда-обратно** из любого крупного аэропорта Италии
в Шри-Ланку и Таиланд, **ведёт историю цен** и присылает в **Telegram** только
реально выгодные варианты — а не всё подряд под фиксированным потолком.

**Направления:** Коломбо (CMB), Бангкок (BKK + Дон Муанг DMK), Пхукет (HKT),
Чиангмай (CNX), Самуи (USM), Краби (KBV).

**Когда бот считает цену «вкусной» (динамический анализ):**
- 📉 новый исторический минимум маршрута;
- 🔥 цена заметно ниже обычной (медианы истории, по умолчанию на −12% и больше);
- 💎 либо просто очень дёшево по абсолютному порогу «отличной цены».

Каждая находка показывает контекст: *«обычно ~520 €, сейчас 430 € (−17%)»*.
Повторно то же предложение по той же цене не шлёт.

- **Даты:** вылет с 23.12.2026, возврат до 31.03.2027 (гибко внутри окна).
- **Источник цен:** Aviasales / Travelpayouts API (по умолчанию цены в евро).
- **Запуск:** GitHub Actions по расписанию (каждые 6 часов) — бесплатно, 24/7.

## Как настроить (примерно 15 минут)

### 1. Токен Travelpayouts
1. Зарегистрируйся на https://www.travelpayouts.com/
2. В личном кабинете зайди в раздел **Разработчикам / API** и создай токен.
3. Скопируй токен — это `TRAVELPAYOUTS_TOKEN`.

*(Маркер `TRAVELPAYOUTS_MARKER` нужен, только если хочешь партнёрские ссылки — необязательно.)*

### 2. Telegram-бот
1. Открой в Telegram **@BotFather**, отправь `/newbot`, задай имя.
   BotFather пришлёт **токен бота** → это `TELEGRAM_BOT_TOKEN`.
2. Напиши что-нибудь своему новому боту (нажми Start), чтобы он мог тебе отвечать.
3. Узнай свой **chat_id**: напиши боту **@userinfobot** — он пришлёт твой ID.
   Это `TELEGRAM_CHAT_ID`.

### 3. Запуск в облаке (рекомендуется)
1. Создай репозиторий на GitHub и загрузи в него эти файлы.
2. В репозитории: **Settings → Secrets and variables → Actions → New repository secret**
   и добавь секреты:
   - `TRAVELPAYOUTS_TOKEN`
   - `TELEGRAM_BOT_TOKEN`
   - `TELEGRAM_CHAT_ID`
   - `TRAVELPAYOUTS_MARKER` *(необязательно)*
3. Вкладка **Actions** → включи workflows.
4. Проверь вручную: **Actions → Track flights → Run workflow**.
   Дальше он будет запускаться сам каждые 6 часов.

> Расписание меняется в `.github/workflows/track.yml` (строка `cron`).
> Помощник: https://crontab.guru

## Локальный запуск (для проверки)

```bash
pip install -r requirements.txt

# Windows PowerShell:
$env:TRAVELPAYOUTS_TOKEN="твой_токен"
$env:TELEGRAM_BOT_TOKEN="токен_бота"     # можно пропустить — тогда вывод в консоль
$env:TELEGRAM_CHAT_ID="твой_chat_id"
python flight_tracker.py
```

Если Telegram не настроен, находки просто печатаются в консоль — удобно для теста.

## Настройки (переменные окружения)

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `CURRENCY` | `eur` | Валюта цен (`eur`, `rub`, `usd`…) |
| `MAX_PRICE` | `650` | Потолок здравого смысла: дороже — вообще не смотрим |
| `GREAT_DEAL_PRICE` | `420` | Всегда оповещать, если дешевле этого |
| `DROP_PCT` | `0.12` | На сколько ниже медианы истории = «вкусно» (0.12 = −12%) |
| `MIN_HISTORY` | `4` | Сколько точек истории нужно, чтобы доверять медиане |
| `DEPART_FROM` | `2026-12-23` | Вылет не раньше этой даты |
| `RETURN_TO` | `2027-03-31` | Возврат не позже этой даты |
| `DEPART_MONTHS` | `2026-12,2027-01,2027-02` | Месяцы вылета для запроса |
| `RETURN_MONTHS` | `2027-01,2027-02,2027-03` | Месяцы возврата для запроса |
| `ITALY_AIRPORTS` | список 12 аэропортов | Аэропорты вылета (IATA через запятую) |

Направления и города вылета настраиваются в начале `flight_tracker.py`.

> **Про историю и «раскачку».** В первые несколько прогонов истории ещё нет,
> поэтому бот присылает только то, что дешевле `GREAT_DEAL_PRICE`. Через несколько
> дней накопится медиана по каждому маршруту, и начнут ловиться просадки цены
> относительно обычного уровня. Файл `history.json` GitHub Actions коммитит обратно
> в репозиторий автоматически.

## Как это работает

1. Для каждой пары «аэропорт Италии → направление» и каждой пары месяцев
   вылет/возврат запрашивается кэш цен Aviasales (эндпоинт `prices_for_dates`).
2. Отбираются билеты в окне дат и дешевле `MAX_PRICE`.
3. По каждому маршруту считается медиана истории цен; «вкусной» считается цена,
   которая бьёт исторический минимум, заметно ниже медианы или ниже
   `GREAT_DEAL_PRICE`. Такие находки идут в Telegram со ссылкой и контекстом цены.
4. `history.json` хранит историю цен по маршрутам и уже отправленные предложения,
   чтобы не дублировать. В GitHub Actions файл коммитится обратно в репозиторий.

## Важные ограничения

- API отдаёт **кэшированные** цены (последние найденные), а не живой поиск в реальном
  времени. Это нормально для мониторинга тренда, но перед покупкой всегда проверяй
  цену по ссылке.
- Для дальних дат (декабрь+) кэш бывает разреженным — чем ближе даты, тем больше
  предложений. Имеет смысл запускать регулярно.
